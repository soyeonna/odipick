# 검색 개편 — 현재 구조 분석

2026-09-13. 기획서 16번 "먼저 분석해서 정리해달라"에 대한 답.

---

## 1. 오류의 뿌리는 하나다

지금 검색은 **문장을 조건으로 바꾸는 단계가 없다.** 낱말을 그대로 태그와 대조한다.

`index.html` 의 `parse()` 함수가 하는 일:

1. 문장에서 정규식 400여 개(`RULES`)를 하나씩 던져 맞는 태그를 `A` 라는 전역 상자에 쌓는다
2. 남은 낱말은 가게 이름 검색어(`NEEDLE`)로 넣는다
3. 화면은 `A` 를 보고 결과를 만든다

여기서 기획서에 적힌 오류가 전부 파생된다.

| 겪는 오류 | 진짜 원인 |
|---|---|
| 총 8만원을 1인 8만원으로 | 금액을 한 개 변수(`BUDMAX`)에만 담는다. 총액/1인 구분 자체가 없다 |
| 동시에 `5만원 이상` 조건이 붙음 | 금액을 구간 이름(`3–5만원` 등)으로 바꿔 태그에 넣는데, 이 변환이 경계에서 어긋난다 |
| 소개팅이 데이트로 | `RULES` 에 소개팅→`sit:데이트` 로 적혀 있다. 애초에 같은 값이다 |
| `너무`·`가능한` 같은 칩 | 낱말을 버리는 기준이 금지어 목록뿐이라 새 말이 계속 샌다 |
| `술집 말고` 가 술집 포함으로 | **부정을 읽는 코드가 없다.** `술집` 이라는 글자만 보고 조건에 넣는다 |
| 조건을 여러 개 눌러도 하나만 맞아도 나옴 | `score()` 가 맞은 개수로 점수만 매긴다. 탈락시키는 단계가 없다 |
| 룸·주차 모르는 곳이 결과에 | 같은 이유. 모름(`null`)을 0점으로 칠 뿐 빼지 않는다 |
| `오늘 7시`인데 지금 영업으로 판단 | `VISIT` 변수는 있으나 '지금 영업'과 섞여 쓰인다 |

**즉 화면을 고치는 문제가 아니라, 문장 → 조건 변환기가 없어서 생긴 문제다.**

## 3. 데이터 옮기기

지금 한 가게가 이렇게 생겼다.

- 사실과 추측이 섞여 있다 (`sitAuto:true` 면 자동 추정인데 화면에선 구분이 없다)
- 모름과 없음이 섞여 있다 (`fac.room` 이 `undefined` 인지 `false` 인지 뜻이 다른데 화면은 똑같이 '미확인')
- 근거가 없다 (누가 언제 확인했는지 대부분 비어 있음)

**한 번에 갈아엎지 않는다.** 지금 구조를 두고 옆에 붙인다.

1. `ownerCheckedAt` / `evidence` — 이미 넣기 시작했다 (소연님 확인 18곳)
2. `fac` 값은 그대로 두되 **`true`/`false`/없음** 세 가지 뜻을 지킨다. 근거 없으면 넣지 않는다
3. 새 필드(`ambience`, `facilities.parking.type` 등)는 필요한 화면을 만들 때 하나씩 추가
4. 중복 매장(원조태평소국밥·아오리의행방불명)은 `kakaoPlaceId` 기준으로 합친다

9. 회귀 테스트

## 5. 위험한 곳

- **`index.html` 이 한 덩어리라 어디를 건드려도 옆이 깨진다.** → 고칠 때마다 `selftest.py` 와 `test_parser.mjs` 를 돌린다
- **정확도를 올리면 결과가 확 줄어든다.** 룸·주차 모르는 곳을 빼면 지금 데이터로는 결과가 거의 안 남는다. 그래서 "조건 하나를 완화한 대안" 화면이 **필수**다. 이게 없으면 정확해질수록 빈 화면이 된다
- **소연님이 직접 확인해준 정보가 덮어써질 수 있다.** → `ownerCheckedAt` 이 있으면 자동 수집이 건드리지 않게 막아야 한다
- **AI 비용.** 검색마다 AI를 부르면 안 된다. 지금 만든 파서는 AI를 전혀 안 쓴다. 정말 모르겠는 문장만 나중에 넘긴다
- **9월 말 공개 일정.** 기획서 전부는 그 안에 못 한다. P0만 맞추는 게 현실적이다
